1. _start_browser_with_url 函数（gui.py 第1939-1971行）
作用：
通过子进程启动一个独立的 Python 脚本 launch_browser_script.py，并传入可选的 URL。在 Windows 下隐藏控制台窗口，并将进程对象保存到 self._browser_process，以便后续管理。启动后立即创建一个守护线程，该线程仅 sleep(3) 秒后退出，可能意图是等待浏览器完全初始化。

潜在问题：

等待线程 wait_for_browser 除了 sleep 3 秒外没有任何实际逻辑，也无法检测浏览器是否成功启动或页面是否加载完成。如果在这 3 秒内浏览器启动失败，调用者无法得知。

如果多次调用 _start_browser_with_url，之前的 self._browser_process 会被覆盖，可能导致无法正确管理之前的浏览器进程。

没有提供关闭浏览器进程的方法（比如终止子进程），可能导致资源泄漏。

建议：

移除无用的等待线程，或者改为真正的检测逻辑（例如通过请求本地端口或检查进程存活）。

提供 stop_browser 方法来终止进程。

考虑使用进程组，以便在程序退出时能一并结束子进程。

2. 验证窗口的浏览器启动（gui.py 第2156-2165行）
这是验证窗口内部启动浏览器的代码，使用了 Playwright 的 launch_persistent_context 启动一个持久化浏览器（带用户数据目录）。headless=False 表示显示浏览器窗口，用于手动验证。这符合预期，因为验证需要用户交互。

潜在问题：

这里的浏览器启动与 _start_browser_with_url 启动的浏览器是两个独立的机制：前者是直接在当前进程中启动 Playwright，后者是通过子进程启动另一个脚本。如果同时运行，会创建两个浏览器实例，可能互相干扰。

没有检查是否已经存在浏览器进程，可能重复启动。

建议：

统一浏览器启动方式，要么全部通过子进程启动，要么全部在当前进程启动，避免两套逻辑。

增加状态检查，避免重复启动。

3. launch_browser_script.py（第17-25行）
这个脚本的内容与验证窗口中的启动代码几乎完全一致，也是使用 Playwright 启动持久化浏览器。说明作者希望通过独立的脚本启动浏览器，以便在子进程中运行，与主 GUI 进程解耦。

潜在问题：

脚本本身可能缺少异常处理和资源清理（如浏览器关闭时的释放）。

如果用户直接关闭浏览器窗口，脚本进程可能仍在后台运行，无法被主程序感知。

建议：

在脚本中添加信号处理，当浏览器窗口关闭时自动退出进程。

主程序可以通过等待子进程结束来得知浏览器已关闭。

4. 验证窗口的关闭处理（gui.py 第2131-2142行）
当验证窗口关闭时，遍历 verify_browser_threads 列表，检查每个线程是否存活，但什么也没做（pass），然后销毁窗口。

潜在问题：

线程是守护线程（daemon=True），主程序退出时会自动终止，但窗口关闭时可能希望浏览器也一并关闭。这里没有显式关闭浏览器进程，导致浏览器可能仍然在后台运行。

遍历线程但没做任何操作，这段代码实际上是无用的。

建议：

应该在线程的 run_browser 函数中存储浏览器对象，并在窗口关闭时通过某种方式（例如使用 atexit 或显式调用 browser.close()）关闭浏览器。

可以维护一个浏览器实例列表，在窗口关闭时遍历关闭。

5. 线程跟踪（gui.py 第2237-2240行）
将启动的线程添加到 verify_browser_threads 列表，为后续的关闭处理做准备。但如上面所述，关闭处理并未真正利用这个列表。

潜在问题：

如果多个验证窗口同时打开，列表会累积大量线程，但没有清理机制。

建议：

每次启动新线程时，可以清理列表中已经结束的线程。

使用 threading.enumerate() 可能比手动维护列表更可靠。

总结与改进方向
这些修复的核心目标是：

通过独立脚本启动浏览器，避免阻塞 GUI。

在验证窗口中使用持久化浏览器，保存登录状态。

管理浏览器进程和线程，以便在窗口关闭时能够清理。

但仍存在以下不足：

进程管理不完善：_browser_process 可能被覆盖，没有提供关闭接口。

线程管理空洞：verify_browser_threads 列表在窗口关闭时未实际使用。

浏览器启动逻辑重复：验证窗口和独立脚本使用几乎相同的代码，容易导致不一致。

缺乏状态同步：主程序无法得知浏览器是否已关闭或登录是否成功。

建议的改进方案：

统一浏览器启动模块，封装一个 BrowserManager 类，负责启动、停止浏览器，并提供状态查询。

在关闭窗口时，通过 BrowserManager 终止浏览器进程（或至少发送关闭信号）。

如果使用 Playwright 的持久化上下文，可以在脚本中监听浏览器窗口关闭事件，自动退出子进程。

考虑使用 subprocess.Popen 的 terminate() 方法来结束子进程。

一、当前粘贴功能为何失效？
在 gui.py 中，文献下载的文本框绑定了 <<Paste>> 事件：

python
self.literature_urls_text.bind("<<Paste>>", on_paste)
绑定的处理函数 on_paste 试图获取选中的文本（get("sel.first", "sel.last")），然后将其中的空格替换为换行。但当您直接粘贴时，通常没有选中任何文本，因此 get("sel.first", "sel.last") 会引发 TclError，导致进入 except 分支，只返回 "break" 阻止了默认粘贴行为，却没有任何实际粘贴效果。这就是“不接受粘贴”的原因。

正确做法：粘贴时应从剪贴板获取内容，而不是从选中文本获取。

✅ 修复方案：重写 on_paste 函数
将 create_literature_config 中的 on_paste 替换为以下代码：

def on_paste(event):
    try:
        # 获取剪贴板内容
        clipboard_text = event.widget.clipboard_get()
        if clipboard_text:
            # 按空格、换行等分隔符分割成多个网址
            urls = clipboard_text.replace('\r\n', '\n').replace('\r', '\n').split()
            # 将每个网址单独一行插入到当前光标位置
            # 如果有选中文本，则替换选中内容
            try:
                # 尝试获取选中范围
                sel_start = event.widget.index("sel.first")
                sel_end = event.widget.index("sel.last")
                event.widget.delete(sel_start, sel_end)
                insert_pos = sel_start
            except tk.TclError:
                # 无选中，则在光标位置插入
                insert_pos = event.widget.index("insert")
            # 将多行文本插入
            for url in urls:
                event.widget.insert(insert_pos, url + '\n')
                # 移动光标到下一行开始
                insert_pos = event.widget.index(f"{insert_pos} +1 lines linestart")
            return "break"  # 阻止默认粘贴
    except Exception as e:
        print(f"粘贴错误: {e}")
        return "break"  # 仍阻止默认，避免混乱
    return "break"
说明：

clipboard_get() 获取系统剪贴板中的文本。

使用 split() 自动按空白字符（空格、换行、制表符）分割，适合一次性粘贴多个网址。

如果有选中文本，则先删除选中内容，再将新网址插入到选中开始位置；否则插入到光标位置。

返回 "break" 禁止默认粘贴行为，由我们自行处理。

def add_urls_from_clipboard(self):
    """从剪贴板读取内容，按空白字符分割，添加到列表框"""
    try:
        clipboard_text = self.root.clipboard_get()
        if not clipboard_text:
            return
        # 按空白字符分割，去除空字符串
        urls = [url.strip() for url in clipboard_text.replace('\r\n', '\n').replace('\r', '\n').split() if url.strip()]
        for url in urls:
            self.literature_url_listbox.insert(tk.END, url)
        self.literature_log(f"📋 已从剪贴板添加 {len(urls)} 个网址", "info")
    except Exception as e:
        self.literature_log(f"❌ 读取剪贴板失败: {e}", "error")

def remove_selected_urls(self):
    """删除列表框中选中的项"""
    selected_indices = self.literature_url_listbox.curselection()
    if not selected_indices:
        return
    # 从后往前删除，避免索引变动
    for i in reversed(selected_indices):
        self.literature_url_listbox.delete(i)
    self.literature_log(f"🗑️ 已删除 {len(selected_indices)} 个网址", "info")

def clear_url_list(self):
    """清空整个列表框"""
    self.literature_url_listbox.delete(0, tk.END)
    self.literature_log("🧹 已清空网址列表", "info")

def add_single_url(self):
    """从输入框添加单个网址"""
